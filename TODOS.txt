================================================================
 ARAH ENDPOINT BACKEND (dev-CMSCORE) — untuk yang BELUM ada endpoint
================================================================
Saat ini SEMUA fitur di atas disimpan lewat /settings (key-value), jadi
TIDAK ADA 404 walau backend belum menambah endpoint khusus. Berikut arah
yang disarankan bila nanti ingin dipindah ke endpoint terdedikasi:

1. MENU (§2)  — sekarang: GET/PUT /settings key 'home.menu'.
   Arah ideal:
     GET  /v1/menus                 -> { top:[], secondary:[], footer:[] }
     GET  /v1/menus/:location       -> MenuItem[]   (location: top|secondary|footer)
     PUT  /v1/menus/:location       -> body { items: MenuItem[] }
   Bila dibuat: ubah menu.service.ts agar getAll/save memanggil /menus,
   bukan settingsService. Kontrak MenuItem (id,label,url,source,ref_id,children)
   sudah final di FE.

2. FOOTER (§6) — sekarang: /settings key 'home.footer' = { columns, copyright }.
   Arah ideal: tetap di /settings (config situs, bukan entitas). TIDAK perlu
   endpoint baru. Sosial tetap di 'social.links'.

3. IDENTITAS SITUS (§8) — sekarang: /settings keys site.title, site.tagline,
   site.logo_media_id. Arah ideal: tetap di /settings.
   CATATAN: site.logo_media_id menyimpan URL (bukan id). Bila backend ingin
   konsisten menyimpan media ID, sediakan GET /v1/media/:id lalu FE resolve
   id -> file_url di useSiteConfig.ts.

4. TEMA (§4) & SECTION (§5) — sudah via /settings (home.theme, home.sections).
   Arah ideal: tetap di /settings.

5. ADS (§1) — sudah ada CRUD /v1/ads. Tidak ada gap endpoint.

6. POPUP (§7) — sudah ada CRUD /v1/popups. Tidak ada gap endpoint.

7. WIDGET (§3) — sekarang: /settings key 'home.widgets' = Widget[].
   Arah ideal bila dipindah ke entitas terdedikasi:
     GET/POST/PUT/DELETE /v1/widgets
     Widget { id,title,placement,source_mode,auto{content_type,sort,limit},
              manual[{id,title,slug}],active,sort_order }
     placement: popular | editorsPick | video | opinion
   Bila dibuat: ubah widget.service.ts (list/saveAll) agar memanggil /widgets,
   bukan settingsService. Kontrak Widget di FE sudah final.
   PRASYARAT mode auto per-kategori: backend perlu menambah filter ?term= /
   ?category= di GET /contents (saat ini hanya type/status/cursor/limit/sort).

8. FILTER LISTING KONTEN (PRASYARAT A1-ideal, A2, A3, B2, B3) — BELUM ADA.
   GET /contents sekarang whitelist: type, status, cursor, limit, sort.
   Tambahan yang dibutuhkan public:
     ?term=<id|slug>  (atau ?taxonomy=&term=) -> widget taxonomy, halaman kategori,
                        infografis, SecondaryNav berbasis data nyata.
     ?author=<id>     -> daftar artikel di halaman penulis (AuthorView).
     ?q=<keyword>     -> pencarian relevan server-side (kini difilter di klien).
     GET /contents/by-slug/:slug -> ArticleView pakai id (slug hiasan).
   Dampak FE saat tersedia: ganti penyaringan klien di useWidgets (taxonomy),
   TaxonomyView, InfographicsView, AuthorView, useSearch -> query param langsung.

9. AUTHORS — DELETE belum ada.
   author.service.ts hanya list/create/update. UI admin (B1) belum bisa hapus.
   Arah ideal: DELETE /v1/authors/:id (cek pemakaian byline sebelum hapus).
   Bila ada: tambah authorService.remove() + tombol hapus + ConfirmDialog.

10. TERM BERWARNA (opsional, untuk B3).
    Public memakai category_color (hardcode di mock). Bila Term punya field warna
    (mis. meta 'color'), ArticleView & kartu kategori bisa konsisten tanpa mock.
    Arah: tambah kolom/meta warna pada Term di backend.
